# V1

## Keep EXT-90 notifications secondary to committed business actions

Publish meaningful order/payment/shipment events through OrderNotificationPublisher after commit; contain persistence/enqueue failures so valid actions and proof cleanup never fail afterward. Laravel database history is authoritative and event/recipient UUIDs deduplicate replay; new payment-review cycles are distinct. The approved design uses queue retries without an outbox, with a documented commit-to-persistence crash gap. Expo jobs use the asynchronous database connection; device registration is customer/account/device/session scoped, logout/revocation/expiry stops sends, and stale provider feedback must not deactivate a refreshed registration. Expose only recipient/audience-scoped history and ownership-checked order metadata.
